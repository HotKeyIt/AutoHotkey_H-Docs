AutoHotkey_H Changes

This page lists changes specific to AutoHotkey_H. For the features AutoHotkey_H adds, see AutoHotkey_H Features. For changes to AutoHotkey v1.1 itself, see Changes & New Features.

The complete history of AutoHotkey_H is available on GitHub.

1.1.37.02 (AutoHotkey_H)

Merged the changes of AutoHotkey v1.1.34 to v1.1.37.02 into AutoHotkey_H (previously based on v1.1.33.10). See Changes & New Features for details. Among others, this adds #Requires, the /include command line switch, A_Clipboard and InputHook improvements.

Fixed non-persistent scripts not exiting after the auto-execute section completed.

Fixed FileInstall in scripts compiled into the resources of AutoHotkey.exe.

Fixed the /iLib switch not writing its output file.

Fixed UnZipRawMemory() and other decompression of password-protected data crashing in scripts which are not compiled.

Fixed IsBOM() checking the wrong memory when the BOM parameter is omitted.

Added SevenZip(), which uses the 7-Zip module embedded in AutoHotkey.exe. Fixed several of its methods (ExtractMem, ExtractMemEx, FindFirst, List and Hash).

Fixed AutoHotkey.dll failing to start a script a second time in the same process (ahkdll, ahktextdll, ahkReload) with a "RegClass" error. This also affected the ANSI build and scripts using #WindowClassMain.

Fixed debuggers (DBGp clients such as SciTE4AutoHotkey and the Notepad++ plugin) showing no global variables. The global context has id 1 again, as in AutoHotkey; the static context of AutoHotkey_H now has id 2.

Fixed ResExist(), ResGet(), ResPut(), ResPutFile() and ResDelete() failing in ANSI builds.

Fixed settings of the previous script, such as SetFormat, leaking into the next script started in the same AutoHotkey.dll.

Fixed C++ exceptions thrown inside a DLL loaded by MemoryLoadLibrary() crashing the process on 64-bit (the module's image base is now reported for as long as the module is loaded, not only during its DllMain).

Fixed memory leaks when a script is terminated in AutoHotkey.dll (tray menu and thread settings) and when reading encrypted lines of compiled scripts.

Fixed ahkgetvar returning the raw bits of floating-point numbers, overrunning its buffer when a variable held a number but was previously assigned a string, and showing an error dialog for invalid variable names.

Fixed ahkassign on read-only variables such as A_TickCount corrupting every empty string of the script. It now returns -1 for read-only variables and invalid names, and when no script is running (as does ahkPostFunction).

Fixed ahkFunction returning an empty string for floating-point results of user-defined functions, heap corruption when a built-in function returned a long number (which could hang the process), and objects returned by a function (also with ahkPostFunction) never being released.

Fixed ahkPause "On" twice or "Off" while not paused leaving the pause state out of balance. An empty string now only retrieves the state.

Fixed the COM interface: ahkgetvar crashed for variables that do not exist, ignored its GetVar parameter and returned nothing for built-in variables; ahkassign did not set its return value, accepted read-only variables and returned -1 as 4294967295.

Fixed AutoHotkeyMini.dll being built as a nearly complete AutoHotkey.dll: the features it is meant to leave out (such as hotkeys, the keyboard and mouse hook, Gui, menus and InputHook) were included, and A_IsMini was 0. It is now about 25% smaller.

Fixed UnZipRawMemory() and ObjLoad() accepting a wrong password, which returned garbage or crashed the process.

Fixed ObjDump() storing negative 32-bit values incorrectly, failing for -2147483648, and leaking the compressed buffer; fixed ObjLoad() crashing for more than 16 objects with shared references and leaking memory.

Fixed ObjLoad() never freeing the nested objects it loaded.

Fixed CriticalObject() never deleting the CriticalSection it created; it is now deleted with the last CriticalObject using it. CriticalObject(obj, 1) and CriticalObject(obj, 2) now return 0 for anything other than a CriticalObject instead of reading invalid memory.

MemoryGetProcAddress() now also accepts an ordinal instead of a function name.

Fixed scripts compiled into AutoHotkey.dll crashing when the dll started them.

Fixed MemoryFreeLibrary() on 64-bit leaving the module's exception handling data registered, which could crash the process at the next exception.

Fixed MemoryLoadString() overrunning a buffer and leaking memory. It now supports the documented BufferPointer, Length and Language parameters (a third parameter up to 0xFFFF is still used as the language).

Fixed ComObjDll() ignoring an invalid CLSID and crashing for dlls that are not COM servers. It now supports the documented ProgID and IID parameters, and objects without IDispatch.

Fixed #DllImport failing when a comma is followed by spaces (as in the documented syntax) and emptying the default value of the last parameter when a return type follows it. Invalid types are now reported as such instead of "This line does not contain a recognized action".

Fixed Struct() and sizeof() crashing with "division by zero" for structures and unions made only of 1-byte fields, and the sizes of LRESULT and POINTER_32 on 64-bit, POINTER_64 on 32-bit and TBYTE (and TCHAR in ANSI builds).

Fixed WinApi functions with signed TCHAR parameters (for example IsCharSpace and ChrCmpI) failing to load.

Fixed DynaCall() crashing when called with more parameters than defined. Excess parameters are now ignored.

Fixed SendInput sending the wrong number of events after a {N} sleep: SendInput a{150}bcd sent only part of bcd and could leave a key down, and SendInput abc{100} read past the end of the event list.

FileInstall now also finds files in a script compiled into AutoHotkey.dll (also when loaded with MemoryLoadLibrary()) and decrypts files stored with the default password.

The documentation is now based on the AutoHotkey v1.1 documentation, with the AutoHotkey_H pages added under AutoHotkey_H Features.
