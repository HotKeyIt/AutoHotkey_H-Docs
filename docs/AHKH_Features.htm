AutoHotkey_H Features

AutoHotkey_H (by HotKeyIt) is a fork of AutoHotkey v1.1 which adds the features described below. This build is based on AutoHotkey v1.1.37.02, so everything else in this documentation applies as well. Pages which describe AutoHotkey_H features are marked with [AHK_H].

For changes to AutoHotkey_H itself, see the AutoHotkey_H changelog. For the history of AutoHotkey v1.1, see AutoHotkey_L New Features and the changelog.

Binaries

File Description
AutoHotkey.exeThe interpreter. In an AutoHotkey_H release, AutoHotkey.dll, AutoHotkeyMini.dll and the resource library are embedded in its resources, which is what AhkThread() and the library functions rely on. It also exports the functions which are available in both the exe and the dll.
AutoHotkey.dllThe interpreter as a module which can be loaded into any process, one script per loaded instance. See AutoHotkey.dll.
AutoHotkeyMini.dllA version of AutoHotkey.dll intended for lightweight threads. A_IsMini is 1 if the script is running in it.
AutoHotkeySC.binThe base file for compiled scripts.

GUI Enhancements

Automatic positioning and resizing of controls

Controls can be moved and resized automatically when the GUI is resized. They are positioned and sized relative to the initial size of the GUI (as shown by Gui Show), and a control never shrinks below its initial size. Each value may be followed by a decimal number (e.g. 2 or 0.5) or a fraction (e.g. 1/3); negative values are also supported. If no value is given, it defaults to 1, so ax, ax1 and ax1/1 are equivalent. The order in which controls are created may matter when the position of a previous control is taken into account.

AX, AY: Move the control horizontally or vertically by the given proportion of the change in GUI width or height. For example, if the GUI becomes 100 pixels wider, ax1/2 moves the control 50 pixels to the right.

AW, AH: Resize the control by the given proportion of the change in GUI width or height. For example, if the GUI becomes 100 pixels wider, aw0.5 makes the control 50 pixels wider.

AXP, AYP: Move the control by the same amount as the previous control.

AXA, AYA: Move the control by the same amount the previous control was moved and resized, so that it stays right of or below it.

AWA, AHA: Resize the control by the same amount as the previous control.

AXR, AWR, AYR, AHR: Reset horizontal or vertical repositioning or resizing.

Scroll bars

The GUI options Scroll, VScroll and HScroll enable both, only vertical or only horizontal scroll bars for a GUI window.

Compiling and Command Line

A script can be compiled with any AutoHotkey_H binary: AutoHotkey.exe, AutoHotkey.dll or AutoHotkeySC.bin. A compiled AutoHotkey.exe or AutoHotkey.dll keeps its full functionality, including running other scripts: the /E or /Execute switch runs a script file instead of the compiled script. A custom version of Ahk2Exe supports these features.

Resource library: Library functions can be stored in the resources of an exe or dll (resource type "LIB", with the upper-case file name as resource name, e.g. LIB\WATCHDIRECTORY.AHK). Scripts running in AutoHotkey.dll also look for library functions in the resources of the exe. This is not supported by AutoHotkeySC.bin.

Compressed resources: Resources may be compressed and encrypted with ZipRawMemory(); AutoHotkey decompresses them automatically, and scripts can use UnZipRawMemory().

Function Libraries

In addition to the local, user and standard libraries, functions may be auto-included from the folder that Lib.lnk in the directory of AutoHotkey.exe points to.
